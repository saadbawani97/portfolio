04

How I work

Build the smallest useful version, launch it, learn from real usage, then iterate. Most early complexity turns out to be a guess about a problem nobody had yet.

  1. Understand — the problem, the users, the requirements.
  2. Define — clear features and user stories, not a wish list.
  3. Plan — architecture, dependencies, resources, delivery.
  4. Build — with the team, not over the top of it.
  5. Test — functionality, UX, edge cases, real-world use.
  6. Launch — a usable MVP beats waiting for perfect.
  7. Learn — from what people actually do with it.
  8. Iterate — and keep going.

I use AI-assisted tools heavily to move faster, and I'm deliberate about where they stop: architecture, requirements, code review, QA and the technical trade-offs stay human. The tool accelerates the work; it doesn't make the judgement calls.
